# ASV Original-Language Alignment

This README was generated by AI and reviewed by the project maintainer.

This project builds a reproducible word- and morpheme-level alignment between
the American Standard Version and documented Greek, Hebrew, and Aramaic source
projections. Accepted alignments are reviewed, validated, compiled into
chapter ledgers, and exported in both English and original-language order.

This repository contains the development process, rules, and reviewed source
judgments. The finished ASV alignments are published separately in USX format
at [openbibleinfo/American-Standard-Version-Bible](https://github.com/openbibleinfo/American-Standard-Version-Bible).

Two corpus-wide views are included under `reports/`:

- [`original-language-diff.html`](reports/original-language-diff.html) is a
  standalone whole-Bible view of every verse where the accepted
  original-language projection differs from its pinned baseline. Red text is
  removed from the baseline and green text is present in the accepted
  projection. It includes textual selections, verse-boundary differences, and
  explicitly supplied parallel material.
- [`kjv-diff.json`](reports/kjv-diff.json) contains the reviewed New Testament
  readings associated with alternatives in ASV footnotes. It records the
  alternate ASV-style English projection, Greek source tokens, alignment
  units, source-selection evidence, and review provenance used by the reader's
  KJV-readings view.

## Two kinds of reproduction

Rebuilding accepted work is deterministic and requires no model account. It
fetches pinned sources, prepares inputs, validates accepted verse files,
compiles ledgers, and renders publications.

Creating a new alignment includes linguistic judgment. `make drive` sends
prepared verse problems to a configured model, validates every returned
object, performs an independent review pass, reconciles the chapter, runs the
deterministic finishing checks, records provenance, and commits the result.
See [`DRIVER.md`](DRIVER.md) for that workflow.

## Setup

Requirements:

- Python 3.10 or newer
- Git
- GNU Make
- Bash
- network access for the pinned source repositories
- a supported model CLI or API credential only when creating new judgments

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
make help
```

Provider SDKs are imported only by the routes that use them. Deterministic
preparation, validation, compilation, and rendering do not call a model.

## Work with an accepted chapter

All chapter-aware commands require an explicit USX-style chapter reference.

```bash
make fetch CHAPTER=1CH.8
make build CHAPTER=1CH.8
make prepare-alignment CHAPTER=1CH.8
make compile-alignment CHAPTER=1CH.8
make validate-alignment CHAPTER=1CH.8
make aligned-usx CHAPTER=1CH.8
make textual-report CHAPTER=1CH.8
```

`make status CHAPTER=1CH.8` reconstructs progress from durable files and names
anything still owed. `make finish CHAPTER=1CH.8` runs the complete deterministic
finishing sequence.

## Create a chapter alignment

```bash
make drive CHAPTER=PSA.15
```

A successful full drive stages all changes and commits by default. Use
`COMMIT=0` to leave a particular run unstaged and uncommitted.

The command is resumable: a repeated invocation reads accepted files, review
receipts, run records, and the halt queue, then skips completed work. A
successful full run commits the finished chapter automatically.

The normal verse passes use bounded, schema-constrained requests. Routes may
select Claude Code, Codex, Anthropic, OpenAI, or synchronous Gemini. Alignment
and review pack verses by default while preserving independent per-verse
validation. See [`DRIVER.md`](DRIVER.md) for stages, routes, checkpoints, and
cost-bearing behavior.

The local CLI transports are noninteractive subprocesses. The Claude Code
route invokes `claude -p`; the equivalent schema-constrained Codex route uses
`codex exec --output-schema`. The driver supplies the complete briefing,
captures the structured response, validates it, and writes the accepted file;
it does not depend on a person conducting an interactive chat for each verse.

## Published process repository

This repository combines the reusable implementation with selected accepted
chapter records. A chapter record contains accepted judgments, review receipts,
a ledger, source provenance, and the decisions that selected its source
projection. The two corpus-wide reports described above are published; verbose
chapter-level validation and textual-projection reports remain reproducible
local outputs. The governing current contracts live once under `config/`.

Prepared verse inputs are deliberately absent because they are mechanical
derivatives. For a published chapter such as `1CH.8`, these commands recreate
them from the pinned sources and recorded textual decisions:

```bash
make fetch CHAPTER=1CH.8
make build CHAPTER=1CH.8
make prepare-alignment CHAPTER=1CH.8
```

The result is written under `data/output/1CH.8/verses/`. Provider state, raw
model traffic, refetchable source trees, and the separately published ASV USX
are not part of the process repository.

## Repository layout

- `config/` — contracts, schemas, source pins, and recorded textual decisions
- `data/alignments/` — accepted verse judgments, reviews, and compiled ledgers
- `src/alignment_research/` — preparation, validation, orchestration, and export
- `scripts/` — command-line entry points
- `jev/` — Jev, which aligns any English translation verse by verse (see its
  [README](jev/README.md))
- `tests/` — deterministic regression tests
- `reports/` — corpus-wide original-language and KJV-associated difference views
- `.claude/skills/align-chapter/` — chapter-level operating instructions
- `output/` — locally generated products, not source material

For agent and contributor operating rules, see [`AGENTS.md`](AGENTS.md).

## Verification

```bash
make test
```

The release includes a compact deterministic suite for its published parsing,
routing, boundary, cleanup, and diagnostic code. It uses only inline and
temporary fixtures. The full development corpus, packaging checks, and broader
internal regression suite are not part of the release.
